# 🔗 QR Convert — روابط QR قابلة للتحديث بعد الطباعة

اطبع رمز QR واحدًا، وغيّر وجهته متى شئت من لوحة تحكم — بلا إعادة طباعة.

الرمز يشير إلى رابط ثابت على GitHub Pages، والصفحة تقرأ الوجهة الحقيقية من
Firestore وتحوّل الزائر إليها فورًا.

---

## 📁 بنية المشروع

```
docs/                     ← ما يُنشر على GitHub Pages
├── index.html            الرابط الجذري
├── 404.html              بوابة كل الروابط الفرعية (تفصيل أدناه)
├── admin.html            لوحة التحكم
├── admin.js / admin.css  منطق وتنسيق اللوحة
├── redirect.js           منطق التحويل المشترك
├── redirect-page.js      ربط المنطق بواجهة صفحتَي التحويل
├── link-utils.js         دوال خالصة (تفسير المسار وفحص الوجهة)
├── redirect.css          تنسيق صفحتَي التحويل
├── shared.css            الهوية البصرية ومتغيّرات الألوان
└── firebase-config.js    إعدادات Firebase (مصدر واحد)

firestore.rules           قواعد الأمان — الحماية الفعلية للنظام
firebase.json             إعداد المحاكي للاختبارات
tests/                    اختبارات القواعد والدوال
docs/reviews/             تقارير مراجعة المستودع
```

### لماذا منطق التحويل في `404.html`؟

GitHub Pages موقع ثابت بلا توجيه من الخادم. لا يوجد ملف اسمه `main`، فطلب
`/QR-Convert/main` يُخدَم من `404.html`. لذلك تبدأ تلك الصفحة بمحاولة
التحويل، ولا تعرض واجهة "غير موجود" إلا بعد فشل البحث فعلًا.

## 🚀 الإعداد من الصفر

### الخطوة 1: إنشاء مشروع Firebase

1. افتح [Firebase Console](https://console.firebase.google.com) وأنشئ مشروعًا.
2. من **Build → Firestore Database** اضغط **Create database** واختر وضع الإنتاج.
3. من **Build → Authentication → Sign-in method** فعّل **Google**، وفعّل
   **Email/Password** إن أردت الدخول ببريد وكلمة مرور.

### الخطوة 2: نسخ إعدادات Firebase

1. **Project settings → Your apps → Web app** (أضف تطبيق ويب إن لم يوجد).
2. انسخ كائن `firebaseConfig`.
3. الصقه في `docs/firebase-config.js` — **ملف واحد فقط**، تستورده كل الصفحات.

> هذه القيم عامة بطبيعتها ومصمَّمة للعمل في المتصفح، وليست سرًا. الحماية
> الحقيقية كلها في `firestore.rules`. راجع [`SECURITY.md`](SECURITY.md).

### الخطوة 3: ضبط قواعد الأمان ونشرها

1. في `firestore.rules`، ضع بريدك في دالة `isAdmin()` مكان الإيميلات الموجودة.
2. انشر القواعد من **Firestore → Rules** بلصقها ثم **Publish**، أو بالأمر:
   ```bash
   npx firebase deploy --only firestore:rules
   ```

**مهم:** القواعد تشترط `email_verified` — أي أن بريد المسؤول يجب أن يكون
مُفعَّلًا في Authentication. بدون هذا الشرط يكفي أن ينشئ أي شخص حسابًا بكلمة
مرور على بريدك ليحصل على صلاحياتك. حسابات Google مُفعَّلة تلقائيًا؛ حسابات
البريد وكلمة المرور تحتاج إرسال رسالة التفعيل.

### الخطوة 4: تفعيل GitHub Pages

**Settings → Pages → Source:** الفرع `main` والمجلد `/docs` ثم **Save**.
انتظر دقائق حتى ينشر الموقع.

ثم في Firebase: **Authentication → Settings → Authorized domains** أضف
`<username>.github.io` وإلا فشل الدخول من الموقع المنشور.

### الخطوة 5: إنشاء أول رابط

1. افتح `https://<username>.github.io/QR-Convert/admin.html` وسجّل الدخول.
2. أضف رابطًا اسمه `main` ووجهته الموقع الذي تريده.
3. جرّب: `https://<username>.github.io/QR-Convert/main` يجب أن يحوّلك فورًا.

### الخطوة 6: إنشاء رمز QR

ضع في مولّد QR الرابط الكامل، مثل:
```
https://<username>.github.io/QR-Convert/main
```

بعدها تُغيَّر الوجهة من اللوحة، والرمز المطبوع يبقى كما هو.

## 🎛️ استخدام لوحة التحكم

| الإجراء | الطريقة |
|---|---|
| إضافة رابط | املأ الاسم والوجهة والوصف ثم **إضافة الرابط** |
| تعديل الوجهة | **✏️ تعديل** — تُحفظ الوجهة القديمة في الأرشيف تلقائيًا |
| عرض الأرشيف | **📚 الأرشيف** — سجل لا يُعدَّل ولا يُحذف |
| تعطيل مؤقت | **⏸️ تعطيل** — الزائر يرى رسالة بدل التحويل |
| حذف نهائي | **🗑️ حذف** — لا يمكن التراجع، وأي QR مطبوع يتوقف |

**اسم الرابط لا يمكن تغييره بعد الإنشاء** لأنه معرّفه في قاعدة البيانات وأي
رمز مطبوع يعتمد عليه. لتغيير الاسم: أنشئ رابطًا جديدًا واحذف القديم بعد سحب
الأرمزة المطبوعة.

## 🧪 الاختبارات

```bash
npm install
npm test            # الدوال الخالصة — بلا شبكة ولا محاكي (10 اختبارات)
npm run test:rules  # قواعد Firestore على المحاكي (15 اختبارًا، تحتاج Java)
npm run test:e2e    # متصفح حقيقي على المحاكي (8 اختبارات)
npm run test:all
```

| المجموعة | ما تغطيه |
|---|---|
| `tests/link-utils.test.js` | تفسير المسار إلى اسم رابط، ورفض الوجهات بمخططات خطرة |
| `tests/rules.test.js` | قراءة الزائر، زيادة العدّاد بواحد فقط، منع تغيير الوجهة تحت غطاء العدّاد، رفض حساب غير مُفعَّل يحمل بريد المسؤول، إخفاء إيميلات المسؤولين، مناعة الأرشيف |
| `tests/e2e.test.js` | التحويل الفعلي من الجذر ومن الروابط الفرعية، زيادة العدّاد قبل مغادرة الصفحة، دورة حياة رابط كاملة من اللوحة، ومنع تنفيذ HTML في الوصف |

**شغّل `npm run test:rules` بعد أي تعديل على `firestore.rules` وقبل نشرها.**

اختبارات المتصفح تحتاج متصفح Playwright (`npx playwright install chromium`)
ومنفذًا إلى `gstatic.com`. في بيئة معزولة، مرّر مجلدًا فيه نسخة محلية من
حزم Firebase عبر `PW_FIREBASE_VENDOR`.

## 🔧 استكشاف الأخطاء

| العَرَض | السبب الأرجح |
|---|---|
| الرابط الفرعي يعرض 404 بلا تحويل | الرابط غير موجود في Firestore أو معطَّل — تحقق من اللوحة |
| "تعذّر الاتصال بالخادم" | القواعد غير منشورة، أو `firebaseConfig` غير صحيح |
| "لا تملك صلاحية" بعد الدخول | بريدك ليس في `isAdmin()`، أو القواعد لم تُنشر، أو بريدك غير مُفعَّل |
| فشل الدخول بحساب Google | النطاق غير مضاف في Authorized domains |
| الوجهة لا تُحفظ | يجب أن تبدأ بـ `http://` أو `https://` — القواعد ترفض غير ذلك |

افتح Console في المتصفح (F12) لرؤية الرسالة التقنية الكاملة.

## 🎨 نظام التصميم

كل الرموز البصرية معرّفة كمتغيّرات في أعلى `docs/shared.css`: الألوان،
مقياس المسافات (خطوة 4px)، الأنصاف، الظلال، والخطوط. غيّرها هناك وحدها
وتنعكس على الصفحات الثلاث معًا.

```css
:root {
  --accent: #4f46e5;
  --canvas: #f7f8fa;
  --s4: 16px;
  --r-md: 12px;
}
```

**الوضع الداكن** تلقائي: كتلة `@media (prefers-color-scheme: dark)` تعيد
تعريف نفس المتغيّرات بقيم داكنة، فلا يعرف بقية الـ CSS أنه موجود.

**الأيقونات** رموز SVG في مستودع أعلى كل صفحة، يُشار إليها بـ `<use href="#i-…">`
من HTML ومن `admin.js`. اختيرت بدل الإيموجي لأن حجمها ولونها ثابتان عبر
الأنظمة وتتبع لون النص في الوضعين.

**الخط** `IBM Plex Sans Arabic` من Google Fonts، وهو تحسين تدريجي: إذا تعذّر
تحميله تعمل الصفحات بمكدّس خطوط النظام في `--font` بلا أي كسر.
