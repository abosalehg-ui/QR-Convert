# مراجعة مِحَك — QR-Convert (الجولة الثانية)

> **نوع المشروع:** تطبيق (أداة ويب ثابتة + Firebase) — لا توجد حلقة لعب ولا محرك.
> **نطاق المراجعة:** كل ملفات المستودع (26 ملفًا، ~5,300 سطر شاملة التوثيق) على الالتزام `2910c1c`، بعد تنفيذ خطة الجولة الأولى (16 بندًا) وإعادة تصميم الواجهة.
> **الدرجة السابقة:** 4.8/10 ← **الدرجة الحالية: 7.3/10**

---

## 1. نظرة عامة سريعة

- نظام روابط QR قابلة للتحديث بعد الطباعة: رمز QR يشير إلى `github.io/QR-Convert/<اسم>`، وصفحة التحويل تقرأ الوجهة من Firestore وتحوّل الزائر، ولوحة تحكم (`admin.html`) يغيّر فيها المسؤول الوجهة بلا إعادة طباعة.
- **البنية:** موقع ثابت على GitHub Pages في `docs/`. التحويل يمر من `index.html` (الجذر) و`404.html` (كل رابط فرعي، لأن GitHub Pages يخدم أي مسار غير موجود منها)، والمنطق مفصول إلى `redirect.js` (Firebase) و`link-utils.js` (دوال خالصة قابلة للاختبار) و`redirect-page.js` (ربط الواجهة).
- **التقنيات:** Firebase JS SDK ‏10.7.1 من CDN (Firestore + Auth)، قواعد Firestore، خط IBM Plex Sans Arabic، اختبارات `node:test` + `@firebase/rules-unit-testing` + Playwright على المحاكي.
- **الحجم:** ~2,300 سطر كود (JS/HTML/CSS/قواعد) + ~1,650 سطر توثيق + ~520 سطر اختبارات.

**الخلاصة:** القفزة من الجولة الأولى حقيقية. الوظيفة الأساسية صارت تشتغل وعليها اختبارات، والـ XSS انقفل، والإيميلات خرجت من المستند العام. اللي باقي مشاكل أصغر، وأخطرها خلل جديد ما كان مذكورًا قبل: **أي رابط ينتهي بشرطة `/` يعلّق على شاشة "جاري التحويل" للأبد**.

## 2. المراجعة التقنية والهندسية (45%)

### 2.1 البنية المعمارية وفصل المسؤوليات — 8/10

الفصل صار نظيفًا: `link-utils.js` دوال خالصة بلا DOM ولا شبكة، و`redirect.js` يستقبل `onStatus`/`onFail` بدل ما يلمس الـ DOM مباشرة، و`firebase-config.js` مصدر واحد للإعدادات. هذا بالضبط اللي خلّى الاختبار ممكنًا.

النقطة الباقية: `docs/admin.js` ملف واحد من ~700 سطر يجمع المصادقة والعرض والعمليات والنوافذ المنبثقة. ما هو كارثي بهذا الحجم، لكن أول ميزة جديدة (QR مولَّد، بحث، ترقيم صفحات) بتخليه صعب. الحل: افصل `modals.js` (من `FOCUSABLE` إلى `confirmDialog`) و`links-repo.js` (عمليات Firestore) عن العرض.

### 2.2 قابلية القراءة والصيانة — 8/10

التسمية واضحة، الدوال قصيرة، والتعليقات تشرح **ليش** لا **وش**. مثال ممتاز في `redirect.js`:

```js
// والعكس أيضًا لا يصح: إطلاق الكتابة بلا انتظار ثم التحويل فورًا يهدم
// الصفحة قبل أن تغادر الكتابة المتصفح، فتضيع كل النقرات ...
await Promise.race([clickWrite, new Promise((r) => setTimeout(r, CLICK_WRITE_BUDGET_MS))]);
```

ملاحظة صغيرة: الإشارات المتكررة "(البند 6)"، "(البند 11)" مربوطة بتقرير المراجعة السابق. بعد سنة ما أحد بيتذكر وش البند 6. اكتب السبب نفسه، وهو مكتوب أصلًا في أغلب الأماكن، واحذف الرقم.

### 2.3 التكرار (DRY) و Code Smells — 7/10

- `docs/index.html` و`docs/404.html`: وسم CSP كامل ومستودع أيقونات SVG مكرران حرفيًا. التعليق `<!-- CSP: راجع الشرح في index.html -->` يعترف بالتكرار. لو تغيّر نطاق في واحد ونُسي الثاني، ينكسر التحويل في نصف الروابط. الحل: بما إنه موقع ثابت بلا بناء، أضف اختبارًا في `tests/link-utils.test.js` يقرأ الملفين ويتأكد أن قيمة CSP متطابقة.
- `docs/admin.js` — `toggleLinkStatus` يقرأ `snapshot.data()` مرتين، والقراءة الثانية بعد الكتابة توحي إنها القيمة الجديدة وهي القديمة:

```js
await updateDoc(doc(db, 'links', linkId), { active: !snapshot.data().active });
showSuccess(snapshot.data().active ? 'تم تعطيل الرابط' : 'تم تفعيل الرابط');
```

الحل: `const wasActive = snapshot.data().active;` واستخدمه في السطرين.

### 2.4 معالجة الأخطاء والحالات الحدّية — 6/10

هنا أغلب ملاحظات الجولة:

**أ) رابط بشرطة أخيرة يعلّق للأبد (تحققت منه بمتصفح فعلي على خادم الاختبار `startSite`):**

| المسار | النتيجة |
|---|---|
| `/main` | ✅ تُحمّل الملفات وتعمل |
| `/main/` | ❌ `‎/main/shared.css` و`‎/main/redirect-page.js` ترجع 404.html بنوع `text/html` → السكربت ما يشتغل → شاشة "جاري التحويل" بلا نهاية وبلا تنسيق |
| `/a/b` | ❌ نفس الشيء |

السبب في `docs/404.html`:

```html
<link rel="stylesheet" href="./shared.css">
<script type="module" src="./redirect-page.js"></script>
```

المسارات النسبية تُحسب من عنوان الصفحة، والعنوان `/QR-Convert/main/` يجعل `./` = `/QR-Convert/main/`. المفارقة إن `resolveLinkName()` تعالج الشرطة الأخيرة صح، لكن الكود اللي يستدعيها ما يوصل له أصلًا. وما فيه مهلة احتياطية، فالزائر ما يشوف حتى رسالة خطأ.

**الحل:** في `404.html` (وفي `index.html` للاتساق) استخدم مسارات مطلقة: `href="/QR-Convert/shared.css"`، `src="/QR-Convert/redirect-page.js"`. البديل `<base href="/QR-Convert/">` يتطلب تغيير `base-uri 'none'` إلى `'self'` في CSP. وأضف حالة `/main/` إلى `tests/e2e.test.js`.

**ب) `hasAdminAccess()` في `admin.js` تبتلع كل خطأ كأنه رفض صلاحية:**

```js
} catch {
  return false;
}
```

مسؤول حقيقي بشبكة متقطعة يشوف شاشة "ليس لديك صلاحية" بإيميله، ويظن إن حسابه انسحب. الحل:

```js
} catch (error) {
  if (error.code === 'permission-denied') return false;
  throw error; // وفي onAuthStateChanged اعرض showError(humanError(error))
}
```

**ج) التعديل غير ذرّي (`editLinkForm` في `admin.js`):** `addDoc(history)` ثم `updateDoc(link)` كعمليتين منفصلتين. لو فشلت الثانية، يبقى في الأرشيف سجل لتعديل ما صار. ولو انحذف الرابط من تبويب ثاني، `oldData` تكون `undefined` و`oldData.url` يرمي `TypeError` ويطلع للمستخدم "خطأ غير متوقع". الحل: `writeBatch` كما في الإضافة، وفحص `exists()` قبلها.

**د) الحذف يكذب على المستخدم (`deleteLink`):** رسالة التأكيد تقول:

> سيُحذف الرابط "${linkId}" نهائيًا **مع أرشيف تعديلاته**

لكن الكود يحذف `links/{id}` و`meta/admin` فقط. Firestore ما يحذف المجموعات الفرعية تلقائيًا، والقواعد تمنع حذف `history` أصلًا (`allow update, delete: if false`). النتيجة: لو أُنشئ رابط جديد بنفس الاسم، يورث أرشيف الرابط القديم. الحل: عدّل الرسالة إلى "الأرشيف يبقى محفوظًا للمراجعة"، واعرض في نافذة الإضافة تنبيهًا إذا للاسم أرشيف سابق.

**هـ) رسالة خطأ مضللة لمسار متعدد الأجزاء:** `/a/b` يعطي `linkName = 'a/b'`، و`doc(db, 'links', 'a/b')` يرمي خطأ مسار غير صالح داخل `try`، فيطلع للزائر "تعذّر الاتصال بالخادم. تحقق من اتصالك بالإنترنت". (حاليًا ما تبين لأن خلل (أ) يسبقها، وبتطلع بعد إصلاحه.) الحل في `resolveLinkName` أو `runRedirect`: إذا الاسم فيه `/` أو ما يطابق `^[a-zA-Z0-9_-]+$` (نفس شرط اللوحة)، استدعِ `onFail('لا يوجد رابط مسجّل باسم ...')` مباشرة بلا شبكة.

## 3. المظهر والتصميم وتجربة المستخدم (30%)

### 3.1 الاتساق البصري — 8/10

نظام تصميم حقيقي: `shared.css` يعرّف المتغيرات (`--accent`، `--s5`، `--r-sm`، `--touch`) ويستخدمها 188 مرة عبر الملفات، مع وضع داكن عبر `prefers-color-scheme`، وأيقونات SVG موحّدة بدل الإيموجي. `redirect.css` فيه ألوان ثابتة (`#0b0d12`، `#4f46e5`، `#f2646b`...)، ومبرّرة في التعليق ("لوحة داكنة ثابتة — الصفحة لحظية ولا ينبغي أن تومض")، لكن الأنظف تعريفها كمتغيرات `--redirect-*` في رأس الملف.

### 3.2 سهولة الاستخدام والتنقل — 8/10

المهمة الأساسية (تغيير وجهة) = نقرة تعديل + حفظ. معاينة الرابط القصير أثناء الكتابة (`linkPreview`) وزر النسخ لمسات موفّقة. صفحة 404 تشرح الاحتمالات ("الاسم حسّاس لحالة الأحرف: link1 ليست Link1") بدل خطأ جاف.

الناقص: ما فيه بحث أو فلترة في قائمة الروابط، والترتيب حسب المعرّف (ترتيب Firestore الافتراضي) لا حسب الإنشاء. مع 30+ رابط بيصير التنقل متعبًا. أضف `orderBy('createdAt', 'desc')` وحقل بحث بسيط.

### 3.3 الاستجابة (Responsive) — 7/10

`.btn-icon` بعرض وارتفاع `var(--touch)` (هدف لمس كافٍ)، ونقاط توقف عند 520/640/720px. ملاحظة: `.brand-mark` بـ 34px تزييني لا تفاعلي، فلا مشكلة. ما قدرت أختبر سلوك الروابط الطويلة جدًا (`link-target`) على شاشة 320px بدون تجربة فعلية، تأكد أن فيها `overflow-wrap: anywhere`.

### 3.4 العربية و RTL — 8/10

فحصته فعليًا، ما اكتفيت بـ `dir="rtl"`:
- ✅ خصائص منطقية: `inset-inline-start/end` في `redirect.css`، وما فيه `margin-left`/`padding-right` فيزيائية في ملفات CSS.
- ✅ حقول الروابط `dir="ltr"` (`newLinkName`، `newLinkUrl`، `editLinkUrl`)، فما تنقلب الروابط.
- ✅ `LOCALE = 'ar-EG-u-nu-latn'` يوحّد الأرقام على 123 مع بقية الواجهة.
- ✅ خط عربي واحد بثلاثة أوزان فقط مع `display=swap`.
- 🟡 `toLocaleString` بالتقويم الميلادي، مقبول، لكن لو الجمهور جهة حكومية سعودية (الإيميل `nrrc.gov.sa`) ممكن يُطلب الهجري: `ar-SA-u-ca-islamic-umalqura-nu-latn`.

### 3.5 إمكانية الوصول (Accessibility) — 8/10

قفزة كبيرة من 3/10: نوافذ `role="dialog"` + `aria-modal` + حبس التركيز + Escape + إعادة التركيز للزر الأصلي، وأزرار أيقونات بـ `aria-label` يذكر اسم الرابط ("حذف الرابط link1")، و`aria-expanded` على زر نموذج البريد، و`role="alert"` للتنبيهات، و`prefers-reduced-motion`.

الناقص: التنبيهات تختفي تلقائيًا (`showError` بعد 8 ثوانٍ)، ومستخدم قارئ الشاشة البطيء ممكن تفوته الرسالة. اجعل رسائل الخطأ تبقى حتى إغلاقها بزر.

### 3.6 التغذية الراجعة — 7/10

`withBusy` يعطّل الزر ويغيّر نصه، ونافذة تأكيد مخصصة قبل الحذف، ورسائل Firebase مترجمة إلى عربية مفهومة (`AUTH_MESSAGES`). لكن خللا 2.4-أ (شاشة تحميل بلا نهاية) و2.4-ب (شاشة "ممنوع" عند انقطاع الشبكة) كلاهما فشل في التغذية الراجعة. في حالة 2.4-أ ما تنفع مهلة احتياطية داخل `redirect-page.js` لأن السكربت نفسه ما يتحمّل، وCSP تمنع السكربت المضمّن في HTML. فالحل هو إصلاح المسارات نفسها.

## 4. المراجعة الأمنية (25%)

السياق: موقع ثابت، و`firestore.rules` هي الحد الأمني الوحيد. المفتاح العلني في `firebase-config.js` **ليس ثغرة** (مصمَّم للمتصفح)، والتوثيق يوضّح هذا.

### 4.1 المفاتيح والأسرار — 8/10

- ✅ ما فيه أسرار حقيقية في الكود. `deploy.yml` المسرّب انحذف وموثّق في `SECURITY.md` مع طلب 2FA.
- 🟡 **بسيط** — `firestore.rules` في `isAdmin()`: إيميلا المسؤولين منشوران في مستودع عام. موثّق كتحسين مؤجّل، والحل المذكور صحيح: Custom Claims (`request.auth.token.admin == true`).

### 4.2 الحقن — 9/10

- ✅ `admin.js` كله `textContent` + `createElement`، ولا `innerHTML` مع بيانات Firestore. `redirect-page.js` يعرض الرسالة بـ `textContent`.
- ✅ `safeTargetUrl()` ترفض `javascript:` و`data:`، والفحص مكرر في القواعد (`d.url.matches('^https?://.*')`).
- ✅ CSP تمنع السكربت المضمّن كطبقة ثانية.

### 4.3 التحقق من المدخلات — 8/10

- ✅ `isValidLink()` تتحقق من النوع والطول والمخطط.
- 🟡 **بسيط** — `isValidLink()` ما تقيّد الحقول المسموحة، فالمسؤول (أو حساب مسؤول مخترق) يقدر يضيف حقولًا عشوائية بأي حجم إلى المستند العام المقروء للجميع. الحل:
  ```
  && d.keys().hasOnly(['url','description','active','clicks','createdAt','lastClicked','updatedAt'])
  ```
- 🟡 **بسيط** — اسم الرابط يُتحقق منه بـ `^[a-zA-Z0-9_-]+$` في الواجهة فقط. أضف في القواعد: `allow create: if isAdmin() && isValidLink() && linkId.matches('^[a-zA-Z0-9_-]{1,64}$');`

### 4.4 الصلاحيات والمصادقة — 7/10

- ✅ `email_verified == true` يسد انتحال البريد بحساب كلمة مرور.
- ✅ `isClickIncrement()` محكمة: حقلان فقط، زيادة بواحد، و`lastClicked == request.time`.
- 🟠 **متوسط** — **تعداد المجموعة كاملة ما زال ممكنًا.** `allow read: if true` على `links/{linkId}` تشمل `get` و`list`، فأي شخص بالمفتاح العلني يقدر ينفّذ `getDocs(collection(db,'links'))` ويسحب كل الوجهات والأوصاف والعدّادات. نقل الإيميلات إلى `meta/` حل نصف ملاحظة الجولة الأولى. التحويل يحتاج `get` لمستند معروف الاسم فقط، واللوحة (اللي تحتاج `list`) للمسؤول. الحل سطر واحد:
  ```
  allow get: if true;
  allow list: if isAdmin();
  ```
  (الأوصاف الداخلية مثل "حملة سرية قبل الإطلاق" تتوقف عن كونها عامة. والتخمين بالاسم يبقى ممكنًا، فلا تعتبرها سرية كاملة.)
- 🟡 **بسيط** — `isClickIncrement()` ما تشترط `resource.data.active == true`، والزيادة غير محدودة بالمعدّل، فأي شخص يقدر يضخّم عدّاد أي رابط (حتى المعطَّل) بحلقة. الأثر: إحصائيات غير موثوقة فقط. الحل الجزئي: أضف `&& resource.data.active == true`. والحد الحقيقي للمعدّل يحتاج Cloud Function أو App Check.
- 🟡 **بسيط** — أرشيف `history`: القواعد ما تتحقق أن `changedBy == request.auth.token.email`، فالسجل "غير القابل للتعديل" يقبل اسم معدِّل مزوّر من أي مسؤول. أضف `&& request.resource.data.changedBy == request.auth.token.email && request.resource.data.changedAt == request.time`.

### 4.5 البيانات الحساسة — 8/10

- ✅ الإيميلات في `meta/admin` و`history` المقروءة للمسؤول فقط، وHTTPS إلزامي عبر GitHub Pages.
- 🟠 **متوسط (توثيقي)** — `SECURITY.md` يقترح جمع IP والمدينة ونوع الجهاز لكل زائر (انظر 2.7). هذا ما هو مطبَّق، لكن وجوده كـ"نصيحة أمان" يشجّع على جمع بيانات شخصية بلا موافقة. احذفه أو أضف تحذيرًا عن الخصوصية.

### 4.6 الاعتماديات — 7/10

- 🟡 Firebase SDK مثبّت على 10.7.1 (أواخر 2023). التثبيت قرار صحيح وموثّق، لكن الإصدار قديم بفروع رئيسية. حدّثه في الملفات الثلاثة دفعة واحدة بعد تشغيل `test:e2e`.
- 🟡 `package-lock.json` مستبعد من git (انظر 2.8)، فما يمكن تشغيل `npm audit` بشكل حتمي. وما شغّلته لأن `node_modules` غير مثبّت.

### 4.7 CORS والترويسات — 7/10

- ✅ CSP مطبّقة في الصفحات الثلاث مع `base-uri 'none'` و`form-action 'none'`، و`frame-src` محصور بنطاق Firebase وGoogle.
- 🟡 `frame-ancestors` غير ممكنة من وسم meta وGitHub Pages ما يسمح بترويسات، فاللوحة قابلة للتأطير (clickjacking). موثّق في التعليق. التخفيف الوحيد هنا: نقل الاستضافة لـ Firebase Hosting (يسمح بـ `headers` في `firebase.json`).
- 🟡 `http://127.0.0.1:8080` و`:9099` في `connect-src` الإنتاجية. الأثر شبه معدوم، لكنه يسمح لأي سكربت محقون بالاتصال بخدمات محلية على جهاز المسؤول. يمكن تركه، أو توليد نسختين من CSP.
